1. What's the difference between interpreted and compiled languages?
   Examples for such languages?
   #+begin_quote
   *Interpreted* languages (like Python) go straight from /source code/ to
   result, while *compiled* languages (like C++) require an intermediate
   step, machine or /object/ code, before they can be run.
   #+end_quote

2. Who does what with what until a C program can be run?
   #+begin_quote
   1) The *user* write /source code/ in an *editor*.
   2) The *user* saves the source code in a =.c= *file*.
   3) The *compiler* translates the =.c= file into *object code* (=a.out=)
   4) The *shell* program executes the *object* (or *machine*) *code*.
   #+end_quote

3. What is the anatomy (dissection) of this command: =printf("Hello\n");=
   #+begin_quote
   1) =printf= is a function defined in the =<stdio.h>= header file.
   2) The function argument is a string ="..."=.
   3) The string consists of a /string literal/ (constant) =Hello= and a
   new line character, =\n=.
   4) The command is delimited by a =;= character.
   #+end_quote

4. Which programming errors do you know, when do they occur, and do
   you have an example?
   #+begin_quote
   1) *Syntax errors* when the language rules are violated, for example
      a missing semicolon - program will not compile.
   2) *Logical errors* when your algorithm does not work, for example
      the wrong formula - program will not crash.
   3) *Run-time errors* when the program is executed - for example when
      you divide by zero - program crashes or behaves unexpectedly.
   4) *Semantic error* when program compiles and runs but produces
      incorrect results due to incorrect meaning - for example, using
      a variable incorrectly.

   *Exercise:* write little programs that produce each of these
   errors. - this is exercise 1.3 in Think C on page 10.
   #+end_quote

** How to learn faster/better & example problem / Extra practice programs
#+attr_html: :width 400px :float nil:
[[../img/summary_1_overview.png]]

I posted this to the Google Chat, prompted by @JacieLynn, who asked
about winning strategies to learn how to program.

Here are a few study strategies that work well for beginners:
- *Short daily practice (15–30 minutes)* beats long sessions once a
  week. Aim for consistency.
- *Predict → run → explain:* Before you run a program, write down what
  you think it will print. Then run it. Then explain (in words) why it
  did that.
- *Trace by hand:* For small programs, go line-by-line and write the
  values of variables after each line. This is one of the fastest ways
  to “see” what the computer is doing.
- *Rewrite from memory:* After you understand an example, close it and
  retype it from scratch. Then compare. This builds independence
  quickly.
- *Make tiny changes (“one change only” rule)*: Change one thing (a
  number, a variable name, a print statement) and rerun. If you change
  multiple things at once, it’s hard to know what caused what.

At the moment, you can't do too much with the few tools you've got. If
you already read the second chapter, you know:

- ~main~ function
- ~printf~ function
- variables to store texts or numbers, e.g.: =age=
- basic types (~int~, ~double~, ~char~), e.g.: =int age=
- assignment, e.g. =int age = 22=

Here is a problem you can try:

*** Exercise: Getting Started with C Programs

These exercises assume you know:
- what a C program looks like (~main~, braces, semicolons),
- how to use ~printf~ *only with string literals*,
- that variables and basic types (~int~, ~double~, ~char~) exist,
but you do *not* yet know format specifiers or input.

Remember: A program can do meaningful work even if it does not display
that work yet.  Printing values is a separate skill that will come
later.

*** Problem 1: Program as a Script

Write a C program that prints a short “story” consisting of *at least
five lines*. Don't forget the program header.

Constraints:
- Each line must be printed using a separate ~printf~ statement.
- Each ~printf~ may only print a string literal.
- No variables are used in the output.

Example structure (content is up to you):
#+begin_example
- Program started.
- First step completed.
- Second step completed.
- Final step completed.
- Program finished.
#+end_example

Focus:
- Program structure
- Order of execution (top to bottom)
- Correct syntax (~printf~, quotes, semicolons, braces)

** Popquiz: Variables and Types (15 min)

10 minutes to answer the questions & then grade yourself and hand the
sheet in if you want your points to be counted as bonus (@ midterms).

1. Which placeholder is used in the ~printf~ function to print an
   integer value?
   #+begin_src C :main yes :includes <stdio.h> <stdlib.h> <string.h> :results output :exports both :noweb yes
     printf("This is an integer: %i.", 100);
   #+end_src

2. What is a variable? How would you define it?
   #+begin_quote
   A *variable* is a *named* *location* (in computer memory) that stores a
   *value*.
   #+end_quote

3. What type of variable would be used to store the value ~'A'~?
   #+begin_src C :main yes :includes <stdio.h> <stdlib.h> <string.h> :results output :exports both :noweb yes
     char letter = 'A';
     printf("You stored the character '%c'.", letter);
   #+end_src

4. In the following *statement*, what's the *variable* name, what's the
   *value*, what's the variable *type*, and what's the *operator*?
   #+begin_example C++
   int age_of_bob = 22;
   #+end_example

   #+begin_quote
   - ~int~ is the variable *type* (integer).
   - =age_of_bob= is the *variable* *name*.
   - ~=~ is the *operator* (assignment).
   - =22= is the variable *value* (integer).
   #+end_quote

5. True or false: "The computer performs addition and subtraction
   before it performs multiplication and division."
   #+begin_quote
   ~FALSE~. The rule of precedence from left to right is PEMDAS:
   Parentheses-Exponent-Multiplication-Division-Addition-Subtraction.
   #+end_quote

   #+begin_src C :main yes :includes <stdio.h> <stdlib.h> <string.h> :results output :exports both :noweb yes
     printf("%i", 5 + 3 * 4 / 2); // 3 * 4 -> 12 | 12 / 2 = 6 | 5 + 6 = 11.
   #+end_src

6. What will the code =printf("%c", 'a' + 1);= print as output?
   #+begin_src C :main yes :includes <stdio.h> <stdlib.h> <string.h> :results output :exports both :noweb yes
     printf("%c \n", 'a' + 1); // b
     printf("%i", 'a' + 1); // 98
   #+end_src

7. What's the difference in output between the two print statements?
   #+begin_src C :main yes :includes <stdio.h> :results output :exports both :noweb yes
     float speed = 100.;
     float time = 10;
     float distance = speed * time;

     printf("A car travelling %.0f mph travels %.0f miles in %.0f minutes.",
            speed, distance, time);
     printf("\nA car travelling %.0f mph travels %.0f miles in %.0f minutes.",
            100., speed * time, 10.);
   #+end_src

   #+begin_quote
   There is no difference in the output at all. The first ~printf~
   statement prints the =distance= computed before, the second computes
   the distance using a composition statement (uses simpler
   expressions).
   #+end_quote

8. For the last assignment, assign the values to the variables in the
   state diagram:
   #+begin_example
     speed      time     distance
   +-------+  +-------+  +-------+
   |       |  |       |  |       |
   |       |  |       |  |       |
   |       |  |       |  |       |
   +-------+  +-------+  +-------+
   #+end_example
   Solution:
   #+begin_example
     speed      time     distance
   +-------+  +-------+  +-------+
   |       |  |       |  |       |
   |  100  |  |  10   |  |  1000 |
   |       |  |       |  |       |
   +-------+  +-------+  +-------+
   #+end_example

9. What is ~\n~ and what does it do?
   #+begin_src C :main yes :includes <stdio.h> <stdlib.h> <string.h> :results output :exports both :noweb yes
