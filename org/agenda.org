1. What's the difference between interpreted and compiled languages?
   Examples for such languages?
   #+begin_quote
   *Interpreted* languages (like Python) go straight from /source code/ to
   result, while *compiled* languages (like C++) require an intermediate
   step, machine or /object/ code, before they can be run.
   #+end_quote

2. Who does what with what until a C program can be run?
   #+begin_quote
   1) The *user* write /source code/ in an *editor*.
   2) The *user* saves the source code in a =.c= *file*.
   3) The *compiler* translates the =.c= file into *object code* (=a.out=)
   4) The *shell* program executes the *object* (or *machine*) *code*.
   #+end_quote

3. What is the anatomy (dissection) of this command: =printf("Hello\n");=
   #+begin_quote
   1) =printf= is a function defined in the =<stdio.h>= header file.
   2) The function argument is a string ="..."=.
   3) The string consists of a /string literal/ (constant) =Hello= and a
   new line character, =\n=.
   4) The command is delimited by a =;= character.
   #+end_quote

4. Which programming errors do you know, when do they occur, and do
   you have an example?
   #+begin_quote
   1) *Syntax errors* when the language rules are violated, for example
      a missing semicolon - program will not compile.
   2) *Logical errors* when your algorithm does not work, for example
      the wrong formula - program will not crash.
   3) *Run-time errors* when the program is executed - for example when
      you divide by zero - program crashes or behaves unexpectedly.
   4) *Semantic error* when program compiles and runs but produces
      incorrect results due to incorrect meaning - for example, using
      a variable incorrectly.

   *Exercise:* write little programs that produce each of these
   errors. - this is exercise 1.3 in Think C on page 10.
   #+end_quote

** How to learn faster/better & example problem / Extra practice programs
#+attr_html: :width 400px :float nil:
[[../img/summary_1_overview.png]]

I posted this to the Google Chat, prompted by @JacieLynn, who asked
about winning strategies to learn how to program.

Here are a few study strategies that work well for beginners:
- *Short daily practice (15–30 minutes)* beats long sessions once a
  week. Aim for consistency.
- *Predict → run → explain:* Before you run a program, write down what
  you think it will print. Then run it. Then explain (in words) why it
  did that.
- *Trace by hand:* For small programs, go line-by-line and write the
  values of variables after each line. This is one of the fastest ways
  to “see” what the computer is doing.
- *Rewrite from memory:* After you understand an example, close it and
  retype it from scratch. Then compare. This builds independence
  quickly.
- *Make tiny changes (“one change only” rule)*: Change one thing (a
  number, a variable name, a print statement) and rerun. If you change
  multiple things at once, it’s hard to know what caused what.

At the moment, you can't do too much with the few tools you've got. If
you already read the second chapter, you know:

- ~main~ function
- ~printf~ function
- variables to store texts or numbers, e.g.: =age=
- basic types (~int~, ~double~, ~char~), e.g.: =int age=
- assignment, e.g. =int age = 22=

Here is a problem you can try:

*** Exercise: Getting Started with C Programs

These exercises assume you know:
- what a C program looks like (~main~, braces, semicolons),
- how to use ~printf~ *only with string literals*,
- that variables and basic types (~int~, ~double~, ~char~) exist,
but you do *not* yet know format specifiers or input.

Remember: A program can do meaningful work even if it does not display
that work yet.  Printing values is a separate skill that will come
later.

*** Problem 1: Program as a Script

Write a C program that prints a short “story” consisting of *at least
five lines*. Don't forget the program header.

Constraints:
- Each line must be printed using a separate ~printf~ statement.
- Each ~printf~ may only print a string literal.
- No variables are used in the output.

Example structure (content is up to you):
#+begin_example
- Program started.
- First step completed.
- Second step completed.
- Final step completed.
- Program finished.
#+end_example

Focus:
- Program structure
- Order of execution (top to bottom)
- Correct syntax (~printf~, quotes, semicolons, braces)

1. Which placeholder is used in the ~printf~ function to print an

2. What is a variable? How would you define it?
   #+begin_quote
   A *variable* is a *named* *location* (in computer memory) that stores a
   *value*.
   #+end_quote

3. What type of variable would be used to store the value ~'A'~?
   #+begin_src C :main yes :includes <stdio.h> <stdlib.h> <string.h> :results output :exports both :noweb yes
     char letter = 'A'; // `char` for character
     printf("You stored the character '%c'.", letter);
   #+end_src

   #+RESULTS:
   : You stored the character 'A'.

4. In the following *statement*, what's the *variable* name, what's the
   *value*, what's the variable *type*, and what's the *operator*?
   #+begin_example C++
   int age_of_bob = 22; // `;` is just the statement delimiter
   #+end_example

   #+begin_quote
   - ~int~ is the variable *type* (integer).
   - =age_of_bob= is the *variable* *name*.
   - ~=~ is the *operator* (assignment).
   - =22= is the variable *value* (integer).
   #+end_quote

5. True or false: "The computer performs addition and subtraction
   before it performs multiplication and division."
   #+begin_quote
   ~FALSE~. The rule of precedence from left to right is PEMDAS:
   Parentheses-Exponent-Multiplication-Division-Addition-Subtraction.
   #+end_quote

   #+begin_src C :main yes :includes <stdio.h> <stdlib.h> <string.h> :results output :exports both :noweb yes
     printf("%.0f", 5. + 3. * 4. / 2.); // 3 * 4 -> 12 | 12 / 2 = 6 | 5 + 6 = 11.
   #+end_src

   #+RESULTS:
   : 11

6. What will the code =printf("%c", 'a' + 1);= print as output?
   #+begin_src C :main yes :includes <stdio.h> <stdlib.h> <string.h> :results output :exports both :noweb yes
     printf("%c \n", 'a' + 1); // b
     printf("%i", 'a' + 1); // 98
   #+end_src

7. What's the difference in output between the two print statements?
   #+begin_src C :main yes :includes <stdio.h> :results output :exports both :noweb yes
     float speed = 100.;
     float time = 10;
     float distance = speed * time;

     printf("A car travelling %.0f mph travels %.0f miles in %.0f minutes.",
            speed, distance, time);
     printf("\nA car travelling %.0f mph travels %.0f miles in %.0f minutes.",
            100., speed * time, 10.);
   #+end_src

   #+RESULTS:
   : A car travelling 100 mph travels 1000 miles in 10 minutes.
   : A car travelling 100 mph travels 1000 miles in 10 minutes.

   #+begin_quote
   There is no difference in the output at all. The first ~printf~
   statement prints the =distance= computed before, the second computes
   the distance using a *composition* statement (uses simpler
   expressions).
   #+end_quote

1. What are the three components required to define an algebra?
#+begin_quote
An algebra consists of:

2) *operations* defined on the elements,

   satisfy.
#+end_quote

2. What is the set used in Boolean algebra and what do its elements
   represent?
#+begin_quote
The set is {0,1}. 1 represents TRUE and 0 represents FALSE. Boolean
algebra operates on these two logical values.
#+end_quote

3. What are the three basic operations in Boolean algebra?
#+begin_quote
The three basic Boolean operations are:
- AND (conjunction)
- OR (disjunction)
- NOT (negation).
#+end_quote

4. What is the result of the Boolean expression: NOT 0 ?
#+begin_quote
NOT 0 = 1. The NOT operation reverses the truth value: FALSE becomes
TRUE and TRUE becomes FALSE.
#+end_quote

5. What does the rule of *commutativity* mean for the AND operation?
#+begin_quote
Commutativity means the order of operands does not matter.  For
example: p AND q = q AND p. Both expressions produce the same result.
#+end_quote

6. What is the result of the Boolean expression: 0 AND 1 ?
#+begin_quote
0 AND 1 = 0. The AND operation is TRUE (1) only when both operands
are 1.  If either operand is 0, the result is 0.
#+end_quote

7. What is the result of the Boolean expression: 0 OR 1 ?
#+begin_quote
0 OR 1 = 1. The OR operation is TRUE (1) when at least one operand
is 1.
#+end_quote

8. What is the result of applying the NOT operation twice: NOT (NOT p) ?
#+begin_quote
NOT (NOT p) = p. Applying NOT twice returns the original value.
#+end_quote

9. What is the value of the Boolean expression: 1 AND 1 ?
#+begin_quote
1 AND 1 = 1. The AND operation produces TRUE only when both inputs are
TRUE.
#+end_quote

10. Why is Boolean algebra important in computing?
#+begin_quote
Boolean algebra forms the mathematical foundation of *digital logic*.
Logical operations such as AND, OR, and NOT correspond to *logic gates*
used to build digital *circuits* and computers.
#+end_quote

   #+end_example

   It doubles the value of =i= in each iteration and runs forever,
   or until your memory is exhausted (like in OneCompiler.com)
   #+end_quote

4. What is wrong with this loop?
   #+begin_example C
     int i = 0; // set loop variable at start
     while (i < 10); { // is i smaller than 10
       printf("%d\n", i); // print i
       i++;  // increase i by one
     }
   #+end_example

   #+begin_quote
   The semicolon after =while (i < 10)= creates an empty loop. The block
   that follows is not part of the loop, so =i= is never incremented
   inside the loop, causing an infinite loop.
   #+end_quote

5. Prints =4 3 2 1 0= - change it to print =5 4 3 2 1= instead.
   #+begin_src C :main yes :includes <stdio.h> <stdlib.h> <string.h> :results output :exports both :noweb yes
     int i = 5;
     while (i > 0)
       {
         printf("%d\n", i--);
       }
   #+end_src

   #+RESULTS:
   : 5
   : 4
   : 3
   : 2
   : 1

   #+begin_quote
   The code prints values starting from 4 down to 0 instead of 5 down
   to 1. This is because =--i= decrements i before printing
   (pre-decrement). If the intention was to print 5 first, =i--=
   (post-decrement) should be used instead.
   #+end_quote

** DONE Review: ~do-while~ loops

1. What is the key difference between a ~while~ loop and a ~do~ loop?
   #+begin_quote
   A ~while~ loop checks its condition before executing the loop body,
   while a ~do~ loop executes the body first and checks the condition
   afterward, guaranteeing at least one execution.
   #+end_quote

2. Why is it recommended to always use braces ~{...}~ with ~do~ loops?
   #+begin_quote
   Because without braces, the structure can be confusing and may be
   mistaken for a ~while~ loop, leading to logical errors.
   #+end_quote

3. In a ~do~ loop, when does the loop terminate?
   #+begin_quote
   The loop terminates when the ~while~ *controlling expression* evaluates
   to 0 (~FALSE~) after the loop body has been executed.
   #+end_quote

4. Why is a ~do~ loop useful for counting the number of digits in an
   integer?
   #+begin_quote
   Because the loop must execute at least once, even if the number is
   0, ensuring that at least one digit is counted.
   #+end_quote

5. What problem occurs when using a standard ~int~ for very large
   numbers like =6565656565= in the digit-counting program?
   #+begin_quote
   *Integer overflow* occurs because ~int~ cannot represent values larger
   than its maximum range [-2^{31},2^31], so a larger type such as ~long
   int~ must be used.
   #+end_quote

** Pop Quiz: Pointers and Memory (10 Questions)

1. What is a *pointer* in C?
   #+begin_quote
   A pointer is a variable that stores the memory address of another
   variable.
   #+end_quote

2. True or False: The operator ~&~ returns the value stored in a
   variable.
   #+begin_quote
   False. The ~&~ operator returns the memory address of a variable.
   #+end_quote

3. Consider the code:
   #+begin_src C
     int x = 10;
     int *p = &x;
     printf("%d\n", *p);
   #+end_src
   What is printed?
   #+begin_quote
   10
   #+end_quote

4. True or False: The expression ~*p~ accesses the value stored at the
   address held by ~p~.
   #+begin_quote
   True.
   #+end_quote

5. What does the following code do?
   #+begin_src C
     int a = 5;
     int *p = &a;
     ,*p = 20;
   #+end_src
   #+begin_quote
   It changes the value of ~a~ to 20 using the pointer.
   #+end_quote

6. True or False: Assigning ~p = 1;~ (where ~p~ is an int pointer) is
   valid and safe.
   #+begin_quote
   False. This assigns an invalid address and produces a compiler
   warning.
   #+end_quote

7. Consider the code:
   #+begin_src C
     int arr[3] = {1,2,3};
     printf("%d\n", *arr);
   #+end_src
   What is printed?
   #+begin_quote
   1 (the first element of the array).
   #+end_quote

8. True or False: The address of a variable changes after assigning a
   new value to it.
   #+begin_quote
   False. The address remains the same; only the value changes.
   #+end_quote

9. What is the relationship between ~*~ and ~&~ operators?
   #+begin_quote
   They are inverse operations: ~*(&x) = x~ and ~&(*p) = p~.
   #+end_quote

10. Consider the code:
    #+begin_src C
      int a = 5, b = 10;
      int *p = &a;
      int *q = &b;
      ,*q = *p;
    #+end_src
    What are the values of ~a~ and ~b~ after execution?
    #+begin_quote
    a = 5, b = 5 (value of a copied into b via pointers).
    #+end_quote
